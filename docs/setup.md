# Setup guide

Tested with Node.js 18+ (developed against v22), Docker, and PlatformIO.

## 1. Install dependencies

```bash
git clone <this repo> && cd bem-control
npm install   # installs backend, web, mobile, and packages/api-client (npm workspaces)
```

## 2. Start infrastructure (Postgres + Mosquitto)

```bash
npm run certs:generate   # generates dev TLS certs + seeds the broker's password/ACL files
npm run infra:up         # docker compose up -d (postgres + mosquitto)
```

`certs:generate` prints a generated `MQTT_PASSWORD` for the backend's own
service account (`bem-backend`) - you'll need it in the next step.

## 3. Configure and run the backend

```bash
cd backend
cp .env.example .env
# fill in JWT_SECRET and MQTT_PASSWORD (from step 2) in .env
npx prisma migrate dev   # creates the schema in Postgres
npm run dev              # http://localhost:4000, ws://localhost:4001
```

`MQTT_DEVICE_HOST` in `.env` should be your machine's LAN IP (not
`localhost`) if you want a real ESP32 or a physical phone to reach it -
`localhost` only works for services running on the same machine.

## 4. Run the web dashboard

```bash
cd web
cp .env.example .env   # defaults to http://localhost:4000 / ws://localhost:4001
npm run dev             # http://localhost:5173
```

Sign up (this creates your organization), then use **Add device** to
provision your first device - you'll get a one-time API key and a QR code.

## 5. Run the mobile app

```bash
cd mobile
cp .env.example .env
# set EXPO_PUBLIC_API_URL / EXPO_PUBLIC_WS_URL to your machine's LAN IP
npm run start   # opens Expo Dev Tools; scan the QR with Expo Go, or press i/a for a simulator
```

The mobile app's own QR scanner (**Scan device**) reads the provisioning QR
code generated by the web dashboard in step 4.

## 6. Flash the firmware (optional - or simulate a device without hardware)

```bash
cd firmware
cp include/secrets.h.example include/secrets.h
# fill in WIFI_SSID/PASSWORD and the ORG_ID/DEVICE_KEY/MQTT_USERNAME/MQTT_API_KEY
# from the provisioning response in step 4
../scripts/generate-firmware-ca-header.sh   # embeds mosquitto/certs/ca.crt into ca_cert.h
pio run --target upload   # flash a real ESP32 over USB
pio device monitor        # view its serial logs
```

**No physical ESP32?** You can simulate one with `mosquitto_pub`/`mosquitto_sub`
against the exact credentials/topics a real device would use - this is how
the whole pipeline was verified during development:

```bash
DEVICE_KEY=<from provisioning>
ORG_ID=<your org id>
MQTT_USER="device-$DEVICE_KEY"
MQTT_PASS="<the one-time API key>"
TOPIC="orgs/$ORG_ID/devices/$DEVICE_KEY/telemetry"

docker run --rm -v "$(pwd)/../mosquitto/certs:/certs" --network host eclipse-mosquitto:2.0 \
  mosquitto_pub -h localhost -p 8883 --cafile /certs/ca.crt \
  -u "$MQTT_USER" -P "$MQTT_PASS" -t "$TOPIC" -q 1 \
  -m '{"temperature":23.6,"humidity":48.1}'
```

That reading should appear on the device's detail page in the web dashboard
within a second, over the live WebSocket connection - no page refresh needed.

## Running backend tests

```bash
cd backend
npm test
```

Tests mock Prisma/MQTT (`tests/*.test.js`) so they don't require the Docker
infra to be running.
